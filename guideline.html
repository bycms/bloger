Overview

Bloger is a personal blog template generator & theme hub that runs entirely in your browser — no server, no build step. You pick a visual theme, generate a complete self-contained blog project folder, open its built-in editor, write posts, and publish the folder anywhere that serves static files (GitHub Pages, Netlify, or even straight from file://).

There are two distinct things here, and the difference matters:

ThingWhat it isWhere
Bloger tool The site you're on now. Browse themes, preview them, edit design tokens, generate a blog folder, and build/save your own themes. This folder — index.html, generator.html, new-theme.html, etc.
Downloaded blog project The folder you get from Generate. Your actual blog, with its own renderer, theme pack, and in-project editor. Fully separate from Bloger. Generated via the browser — a ZIP you download.

Quick start

Because Bloger loads theme files with fetch(), browsers block it when the page is opened over file://. Start a local server first:

A

Start the server

Double-click serve.bat (requires Python), or run:

# from the bloger folder
python -m http.server 8080
B

Open the hub

Visit http://localhost:8080. The Bloger theme gallery appears.

No server? Use GitHub Pages
The whole tool is pure static and deploys to GitHub Pages as-is (a .nojekyll file and a ready workflow are included). See Publish it.

1 · Browse themes

The hub (index.html) shows a gallery of themes, each with a live preview inside its card (rendered exactly as the downloaded blog would look). Every theme card offers three actions:

ActionWhat it does
PreviewOpen preview.html?theme=<id> — a full-page live preview of that single theme in the blog shell layout.
GenerateOpen the generator to create your blog from this theme.
ForkOpen the theme builder pre-loaded with that theme so you can remodel it into your own and save/download it.

Themes you built and saved in the theme builder also appear here under Your saved themes, ready to preview, generate, or edit again.

2 · Generate a blog

Click Generate on any theme to open generator.html?theme=<id> — a Word-like trial editor with a live preview. This is your chance to:

  • Set site details — title, subtitle, bio, accent color, and more.
  • Write posts with the block editor (headings, paragraphs, quotes, lists, tables, images, code, dividers).
  • Tune design tokens in the Design tokens panel — fonts, sizes, colors, layout — and watch the live preview update.
✓

Download your blog

Click Download to receive a self-contained project folder (a ZIP): its own index.html, edit.html editor, rendering engine, the compiled theme pack, and your seed data baked in.

Fully self-contained
The downloaded folder works on file:// and on GitHub Pages / Netlify. A .nojekyll file is included. You don't need Bloger at all after this point.

3 · Edit your blog

Unzip the downloaded folder. Your blog renders from localStorage (falling back to the config.js seed). Everything is edited in the browser:

1

Open the blog

Open index.html to see your homepage: a slim topbar (sidebar toggle + site title + Edit), a foldable sidebar listing every post's title + date, and the main content area.

2

Open the editor

Click Edit (site-wide) or Edit on any post to open edit.html. There you can edit site settings and posts with the same block editor, switch themes among the packs in the folder, and Save to localStorage.

3

Reload to see changes

After saving, reopen or refresh index.html — your edits appear because they live in that browser's localStorage.

Per-browser saving
Edits are saved to the current browser's localStorage, so they stay on this device — that's how a server-less, self-contained blog keeps everything in your hands. To move your edits to another browser or machine, manage the config.js seed directly.

4 · Publish it

Both Bloger itself and every downloaded blog folder are pure static and deploy with no build step.

WhereHow
GitHub PagesUpload the blog folder and serve index.html, or push this repo (Bloger) with the included workflow at .github/workflows/deploy.yml and enable Settings → Pages → Source: GitHub Actions. A .nojekyll is included so themes/ folders aren't dropped.
Netlify / any static hostDrop the blog folder in. No configuration needed.
Local / offlineJust open index.html — it works over file://.

5 · Build a theme

Open Build a theme (new-theme.html) from any toolbar. This is the theme generator — the way to create your own visual identity:

  1. Name your theme and give it an id.
  2. Tune design tokens — page colors, fonts, sizes, corner radius, layout — with a live shell preview updating as you go.
  3. Save it to this site's localStorage so it appears as a saved theme on the hub, and
  4. Download it as a theme pack — themes/<id>.js + manifest.json + README.
→

Use a saved theme in a blog folder

Copy the pack into the blog folder's themes/, add it to themes/index.js, then pick it in edit.html.

→

Register a theme with Bloger (built-in)

Copy the theme source into themes/<your-theme>/, customize manifest.json, index.html, post.html, and assets/, then add an entry to themes.json:

{ "id": "your-theme", "name": "Your Theme", "description": "A short blurb" }

Reload the hub — your theme appears in the gallery. Removing a theme is just removing its folder and its themes.json entry.

Themes are pluggable folders — add a folder + register it and it shows up without touching core code. A reference starter lives at themes/_starter/, and the full authoring spec is in docs/THEME-SPEC.md.

Design tokens

Bloger ships a design-token system so you can customize a blog without touching theme CSS. Tokens cover page-level and block-type-specific font family/size/weight/ color, line height, corner radius, content width, and page arrangement. They map to CSS custom properties (--be-…) that themes consume.

  • The generator's Design tokens panel edits them for the current generation.
  • The theme builder's Design tokens panel edits them for your saved theme.
  • Theme defaults live in each manifest's design section.

The canonical schema is in js/design.js — that's the extension point if you want to add brand-new tokens.

What's in the downloaded project

Every blog folder you download is a self-contained project:

blog/
├── index.html      # blog homepage (topbar + foldable sidebar), upload this to Pages
├── edit.html       # in-project editor: settings, posts, theme switch, save
├── app.js         # the folder's own rendering engine (shell layout)
├── edit-app.js     # editor page logic
├── editor.js/css   # Word-like block editor
├── config.js       # seed data (site, posts, design)
└── themes/         # compiled theme packs + registry (themes/index.js)
    ├── <id>.js      # compiled pack (window.THEMES[<id>])
    └── index.js     # theme registry
No theme generator in the folder
Blog folders do not include a theme generator — themes are built on this site (Bloger), then packs are copied into the folder. If you want to tweak a theme, visit the generator page and swap the pack.

Notes & FAQ

TopicDetail
Why do I see a message about a server? Bloger reads themes with fetch(), which browsers block over file://. Use serve.bat or deploy to GitHub Pages. The downloaded blog folder works over file://.
Where do my edits live? In the browser's localStorage of the downloaded project, with config.js as the seed fallback. Export/copy config.js to move data between browsers.
Can I add more themes to my folder? Yes. Drop a theme pack into themes/, register it in themes/index.js, and it appears in edit.html's theme switcher.
What post blocks are supported? Heading, paragraph, quote, list, table, image, code, and divider — composed as block objects in the editor.
Where can I learn to write themes? Read docs/THEME-SPEC.md for the full schema and conventions, and copy themes/_starter/ as a template.
