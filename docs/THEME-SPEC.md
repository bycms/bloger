# Bloger Theme Specification

This document is the authoritative guide for building themes for Bloger. A theme is a folder that
Bloger previews and compiles into a **theme pack** that ships inside every generated blog project.
Themes are **pluggable**: no core code changes are required to add or remove one.

---

## 1. Folder layout

```
themes/<theme-id>/
├── manifest.json      # required — describes the theme
├── index.html         # template for the blog home page
├── post.html          # template for a single post page
└── assets/
    ├── style.css      # copied into the pack (tokens allowed, e.g. {{accent}})
    └── main.js        # theme behaviour, injected at runtime
```

The theme `id` (the folder name) must be lowercase, hyphenated, and URL-safe.

---

## 2. `manifest.json`

```json
{
  "id": "my-theme",
  "name": "My Theme",
  "description": "A short description shown in the gallery.",
  "version": "1.0.0",
  "author": "You",
  "entry": "index.html",
  "colors": {
    "bg": "#ffffff",
    "fg": "#111111",
    "muted": "#666666",
    "line": "#e5e5e5"
  },
  "config": [
    { "key": "title", "label": "Blog title", "type": "text", "default": "My Blog", "required": true },
    { "key": "accent", "label": "Accent color", "type": "color", "default": "#111111" }
  ],
  "copy": [
    "assets/style.css",
    "assets/main.js"
  ],
  "templates": {
    "index.html": { "path": "index.html", "tokens": ["title", "subtitle", "accent", "year", "postList", "editSite"] },
    "post.html":  { "path": "post.html",  "tokens": ["title", "accent", "year", "postTitle", "postDate", "postContent", "postNav", "editPost", "editSite"] }
  }
}
```

### Fields

| Field | Required | Type | Description |
| --- | --- | --- | --- |
| `id` | yes | string | Theme id (matches the folder name) |
| `name` | yes | string | Display name in the gallery |
| `description` | no | string | One-line description |
| `version` | no | string | Theme version |
| `author` | no | string | Author name |
| `entry` | yes | string | Home page filename (always `index.html`) |
| `colors` | no | object | Reference palette (informational) |
| `config` | no | array | Schema for the generator's config form (see below) |
| `copy` | yes | array | Asset files compiled into the theme pack |
| `templates` | yes | object | Template mapping for `index.html` and `post.html` |

### `config` schema

Each entry: `key` (identifier), `label`, `type` (`text` / `textarea` / `color` / `select`),
`default`, `required`, `options`, `hint`.

> **Runtime note:** the in-project editor (`edit.html`) exposes a fixed set of site fields:
> **title, subtitle, bio, accent**. Keep your `config` keys to these four so adopters can edit
> them. Any key becomes a token (e.g. `accent` → `{{accent}}`) usable in templates and CSS.

---

## 3. Tokens (runtime substitution)

Templates are **content-only**: the runtime provides the topbar + foldable sidebar shell, so
templates must not include a site header, footer or navigation. Templates keep `{{token}}`
placeholders that the runtime substitutes at render time.

### Available in every page

| Token | Replacement |
| --- | --- |
| `{{title}}` | Blog title |
| `{{subtitle}}` | Tagline |
| `{{bio}}` | Bio |
| `{{accent}}` | Accent color |
| `{{year}}` | Current year |

### Available only in `index.html`

| Token | Replacement |
| --- | --- |
| *(hero / empty-state content)* | `index.html` is rendered when there are no posts, e.g. a "write your first post" hero. Use `{{title}} {{subtitle}} {{bio}} {{year}}`. |

### Available only in `post.html`

| Token | Replacement |
| --- | --- |
| `{{postTitle}}` | Post title |
| `{{postDate}}` | Post date |
| `{{postContent}}` | Rendered post body |

The **sidebar** (all post titles + datetimes), the **topbar** (toggle, site title, Edit link) and
the footer are generated by the runtime — never put them in templates.

### Assets

`assets/style.css` and `assets/main.js` are compiled into the pack verbatim. Tokens in CSS are
substituted at runtime too — put `{{accent}}` in a custom property so adopters' color choices flow
through:

```css
:root { --accent: {{accent}}; }
```

The `{{tokens}}` in `index.html` / `post.html` templates are **body-only**: the `<head>` and any
`<link>`/`<script src>` asset tags are stripped during compilation (assets live inside the pack).

## 4. Block model (post content)

Posts are an array of block objects. The editor (both in Bloger and in the downloaded `edit.html`)
lets adopters compose these with a Word-like interface: type `/` for the block menu, or use
Markdown shortcuts.

| Block | Object | Markdown shortcut |
| --- | --- | --- |
| Heading | `{ type:'heading', text, level }` (1–3) | `# text`, `## text`, `### text` |
| Paragraph | `{ type:'paragraph', text }` | — (default) |
| Quote | `{ type:'quote', text }` | `> text` |
| List | `{ type:'list', ordered, items:[] }` | `- item` / `1. item` |
| Table | `{ type:'table', rows:[[cell,…],…] }` | via `/` menu |
| Image | `{ type:'image', url, caption }` | `![alt](url)` |
| Code | `{ type:'code', text, language }` | ` ``` ` |
| Divider | `{ type:'divider' }` | `---` |

Inline `**bold**`, `*italic*` and `` `code` `` are supported in text blocks. The rendered body is
inserted into `post.html` at `{{postContent}}`.

## 5. The downloaded project

Bloger's generator produces a **self-contained, JS-driven** blog folder:

```
<project>/                    (folder name = slugified blog title)
├── index.html                # the blog homepage — render it (or upload to Pages)
├── edit.html                 # the in-project editor: switch theme, edit, save to localStorage
├── app.js                    # the project's OWN rendering engine (topbar + sidebar shell)
├── edit-app.js               # editor page logic
├── editor.js, editor.css     # Word-like block editor
├── config.js                 # seed data (site, posts, design)
├── themes/
│   ├── index.js              # theme pack registry (id → file)
│   └── <id>.js               # compiled theme pack (window.THEMES[id])
└── .nojekyll                 # lets Pages serve the folder as-is
```

- **`index.html`** is a renderable shell — it never contains raw `{{tokens}}`. It renders the blog
  from data stored in `localStorage`, falling back to the seed in `config.js`. The layout is a
  **topbar + foldable sidebar** (every post's title + datetime) + a clean main content area.
  Posts are viewed via hash routing (`#/post/<id>`).
- **`edit.html`** edits the same data and **saves to localStorage** in the adopter's browser. It can
  **switch themes** among the packs listed in `themes/index.js`.
- **`app.js`** is the project's own rendering engine; the theme packs are self-contained
  (`themes/<id>.js` defines `window.THEMES[id]` with embedded content templates, CSS, design tokens
  and behaviour). No external dependencies.
- Blog folders **do not include a theme generator** — themes are built on the Bloger site and
  downloaded as packs (see below).
- Everything works over `file://` (no server) and when uploaded to **GitHub Pages / Netlify**
  (`.nojekyll` included).

### Theme packs (install into a folder)

Themes are generated on the Bloger site (`new-theme.html`) and downloaded as **theme packs**
(`themes/<id>.js` + `manifest.json` + README). To add a pack to a blog folder:

1. Copy `themes/<id>.js` into the folder's `themes/`.
2. Add it to `themes/index.js`:

   ```js
   window.THEME_PACKS = [ { "id": "<id>", "file": "themes/<id>.js" } ];
   ```

   (keep any existing entries — a folder can hold many packs).
3. Open `edit.html`, pick the theme from the switcher, and Save.

The folder ships with **only the selected theme pack** by default. To add more packs later, drop a
pack file into `themes/` and add one line to `themes/index.js` — the editor's theme switcher picks
them up automatically.

## 6. Registering / unregistering a theme

### Register (make it appear in the gallery)

Add an entry to the root `themes.json`:

```json
{
  "themes": [
    { "id": "minimal", "name": "Minimal", "description": "..." },
    { "id": "your-theme", "name": "Your Theme", "description": "A short blurb" }
  ]
}
```

Reload the hub (`index.html`) — the theme appears with a live preview and a Generate entrance.
**No core code changes are needed.**

### Unregister

Remove the theme's folder from `themes/` **and** remove its entry from `themes.json`.

---

## 7. Conventions & tips

- Keep the default theme (`themes/minimal/`) intentionally spare — pure black/grey/white, no radius.
- Use the `{{accent}}` token so adopters can restyle without editing CSS.
- Always include `assets/style.css` (and `main.js` if you use it) in `copy`.
- Put behavior in `assets/main.js`, not inline scripts in templates.
- Test your theme by registering it and using **Preview** in the gallery.
- Starter theme: use the "Build a theme" page (`new-theme.html`) or copy `themes/_starter/`.

## 8. Design tokens (customization system)

Bloger ships a **design-token system** as the foundation for per-blog customization. It lets a
theme (or an adopter) customize page-level and **block-type-specific** properties — font family,
font size, font weight, color, line height, corner radius, content width, and page arrangement —
without editing theme CSS.

### Where tokens live

- **Schema (canonical definitions):** `js/design.js` — `Bloger.Design.PAGE_TOKENS` and
  `Bloger.Design.BLOCK_TOKENS`. Each token definition declares its `cssVar`, `type`
  (`number` / `color` / `font` / `select`), `unit`, `default`, `options` and `label`.
- **Theme defaults:** a theme's `manifest.json` has a `design` section (`page` + `blocks`)
  overriding the schema defaults for that theme.
- **Adopter overrides:** set in the generator's **Design tokens** panel; merged over the theme
  defaults at generation time.

### Example manifest `design` section

```json
"design": {
  "page": {
    "cornerRadius": 0,
    "maxWidth": 680,
    "pageBackground": "#ffffff",
    "textColor": "#111111",
    "mutedColor": "#6b6b6b",
    "borderColor": "#e0e0e0",
    "bodyFontFamily": "system-ui",
    "arrangement": "single-column"
  },
  "typography": {
    "h1": { "fontSize": 30, "fontWeight": 700, "lineHeight": 1.25, "letterSpacing": -0.02, "color": "#111111" },
    "h2": { "fontSize": 22, "fontWeight": 700, "lineHeight": 1.3, "color": "#111111", "margin": 34 },
    "h3": { "fontSize": 19, "fontWeight": 700, "lineHeight": 1.3, "color": "#111111", "margin": 28 },
    "small": { "fontSize": 13, "color": "#6b6b6b" },
    "link": { "color": "#111111", "hoverColor": "#111111", "underline": "underline", "thickness": 1 }
  },
  "blocks": {
    "paragraph": { "fontSize": 16, "lineHeight": 1.7, "color": "#111111" },
    "quote": { "color": "#6b6b6b" },
    "list": {},
    "table": { "fontSize": 14 },
    "image": { "cornerRadius": 0 },
    "code": { "fontFamily": "ui-monospace, monospace", "fontSize": 13 },
    "divider": {}
  },
  "motion": { "duration": 0.18, "easing": "ease" }
}
```

> Headings are styled through the `typography` scope (h1/h2/h3), not as a block — a `heading`
> block renders as `<h2>`/`<h3>` and picks up the matching level's tokens. The `shell` scope
> (topbar/sidebar/footer) follows the same leaf shape as the runtime `SHELL_CSS`.


### How it is applied

`Bloger.Design.styleBlock(design)` produces a `:root { --be-…: … }` block that is:

1. Embedded into the compiled theme pack (`designCss`) and the seed `config.js` (`design`).
2. Injected at runtime by the downloaded project (`app.js`) and by Bloger previews (`render.js`).
3. Consumed by theme stylesheets via `var(--be-…)`, e.g.:

   ```css
   body { color: var(--be-text, #111111); font-size: var(--be-body-size, 16px); }
   .post-body h2 { font-size: var(--be-h2-size, 22px); line-height: var(--be-h2-lh, 1.3); margin-top: var(--be-h2-margin, 34px); }
   .post-body img { border-radius: var(--be-image-radius, var(--be-corner-radius, 0px)); box-shadow: var(--be-image-shadow, none); }
   ```

### Current tokens → CSS variables

| Scope | Token | CSS variable |
| --- | --- | --- |
| page | corner radius | `--be-corner-radius` |
| page | content width | `--be-max-width` |
| page | page / text / muted / border colors | `--be-page-bg`, `--be-text`, `--be-muted`, `--be-border` |
| page | body font | `--be-body-font` |
| page | arrangement | *(layout class, future work)* |
| block | font family | `--be-<block>-font` |
| block | font size | `--be-<block>-size` |
| block | line height | `--be-<block>-lh` |
| block | color | `--be-<block>-color` |
| block | font weight | `--be-<block>-weight` |
| block | corner radius | `--be-<block>-radius` |

Block keys: `heading`, `para`, `quote`, `list`, `table`, `image`, `code`.

### Extending the system

To add a new design token later (e.g. letter-spacing, text alignment, spacing scale):

1. Add a definition to `Bloger.Design.PAGE_TOKENS` or the relevant block set in `js/design.js`
   (give it a `cssVar`, `type`, `unit`, `default`, `label`).
2. Reference the variable in the theme's CSS (`var(--be-…)`).
3. The generator's Design tokens panel and the runtime pick it up automatically — no other wiring
   needed.

Page **arrangement** (`single-column` / `with-sidebar`) is defined in the schema and UI today;
applying the sidebar layout classes is the next piece of builder work.
